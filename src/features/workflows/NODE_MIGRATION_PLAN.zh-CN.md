## 1. 阶段目标

第一阶段已经完成 Start、HTTP、LLM、End 四节点真实闭环、智能体生命周期、节点 registry、变量校验、真实 SSE 状态机和调试详情。

第二阶段以现有四节点标准为基线，逐个迁移参照项目节点库中尚未完成的 11 个业务节点。参照项目前端是功能字段和交互语义的迁移主体；现有后端用于联调、确认协议差异和问题归属，不能因为后端暂未实现就删除参照前端已有的配置能力。每个节点都必须完成保存恢复、变量传递、连线语义、运行状态和调试详情，不能只迁移节点外观。

本阶段采用“一次只迁移一个节点”的推进方式。当前节点完成并验收后，才进入下一个节点。

## 4. 每个节点的固定实施流程

### 4.1 先分析参照前端完整业务契约

修改代码前必须先完整检查参照项目前端，再使用后端确认联调差异：

- 参照项目的节点默认配置、配置面板和序列化逻辑。
- 后端 `FlowNodeType`、对应 `NodeExecutor` 和已有协议示例；后端仅用于确认兼容性和问题归属。
- `inputs`、`outputs`、`flowNodeType`、`catchError` 和分支字段。
- 变量引用格式、允许的变量类型以及运行时解析方式。
- 节点 SSE、`message` SSE、流程终态和调试输入输出。

参照前端已存在的成熟字段和交互原则上完整迁移。后端缺少实现时仍保留前端配置、序列化和反序列化，并登记到差异台账；不得静默隐藏或删除。参照项目明确标记为 Mock、占位、开发中且没有实际配置闭环的内容，仍需单独分析后决定是否迁移。

### 4.2 建立独立节点模块

每个节点必须独立注册到 `NODE_MODULE_REGISTRY`，至少提供：

- `backendType`
- `backendRunnable`
- `definition`
- `createDefaultConfig`
- `ConfigPanel`
- `ExecutionDetails`
- `getOutputs`
- `getReferences`
- `serialize`
- `parse`
- `validate`
- `connection` 或动态连接规则

迁移完成后，应从 `placeholderNodeModules` 删除对应占位实现。

### 4.3 建立独立配置契约

节点自己的 contract 文件负责：

- 默认配置
- 配置规范化
- 后端序列化
- 后端反序列化
- 旧数据兼容
- 输入输出定义
- 业务校验

公共序列化、解析、校验、节点库和连接逻辑继续通过 registry 调度，不新增不断扩张的节点类型分支。

### 4.4 UI 对齐宿主项目

配置面板必须使用：

- AI-flow-admin 现有 shadcn 组件。
- Tailwind 语义 Token。
- 现有明暗主题。
- 统一右侧 Dock。
- 现有字段、变量选择器、提示和错误反馈样式。

只复用参照项目的业务协议和交互语义，不复制其组件库和视觉实现。

### 4.5 完成变量与连线闭环

每个节点必须明确并实现：

- 可引用的上游输出及允许类型。
- 对下游公开的输出字段及类型。
- 固定值与变量混合输入。
- 最大输入和输出连线数量。
- 成功分支、异常分支或动态业务分支。
- 无效节点、无效字段、跨支路引用和类型不匹配校验。

画布变量引用继续统一使用：

```text
{{nodeId.outputKey}}
```

### 4.6 接入运行状态和调试详情

节点必须接入现有真实 SSE 状态机：

- `idle`
- `running`
- `success`
- `error`
- `cancelled`
- `skipped`

调试详情至少包含：

- 后端解析后的 inputs
- outputs
- 状态码
- 耗时
- 摘要和执行日志
- 错误信息
- 必要的敏感字段递归脱敏

### 4.7 完成保存和恢复闭环

必须验证：

- 新节点默认配置正确。
- 保存后的 Module JSON 符合真实后端协议。
- 刷新后可完整反序列化节点、配置、输出和连线。
- 后端旧数据只有可规范化差异时不产生错误 dirty。
- 不支持或无法恢复的数据不会被静默丢弃。
- 删除节点、动态输出或分支时同步清理失效连线。

## 7. 循环节点专项边界

循环体是本阶段最后一个节点，因为它不只是一个普通画布节点。完成循环迁移必须同时交付：

- `loopRun` 可拖拽业务节点。
- `loopRunStart` 内部循环入口。
- `loopRunBreak` 内部循环终止节点。
- `parentNodeId`、children 或后端实际采用的嵌套关系。
- 子流程序列化和反序列化。
- 循环项、索引和循环结果变量。
- 内外层连线、变量作用域和退出语义。
- 嵌套节点运行状态和调试详情。

循环体未满足以上全部条件时，不得标记为 `已完成`。

## 8. MCP 后续处理

MCP 不属于当前 11 个参照节点迁移范围。只有以下条件具备后再建立独立阶段：

- 后端具有明确且稳定的 `flowNodeType`。
- 已存在真实执行器和输入输出协议。
- 已明确服务、工具和鉴权配置的数据结构。
- 已明确工具选择、变量映射、错误处理和 SSE 行为。
- 可通过真实后端完成保存、恢复和运行验收。

在此之前，MCP 继续保持“即将推出”，不使用前端 Mock 冒充完成。

## 9. 维护规则

- 每次只推进表格中的一个节点。
- 开始实施时将状态改为 `实施中`。
- 代码完成但未做真实后端验收时改为 `待验收`，不能提前标记完成。
- 真实验收全部通过后改为 `已完成`，并补充验收日期和关键结论。
