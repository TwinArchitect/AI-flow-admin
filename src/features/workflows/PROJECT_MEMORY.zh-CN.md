## 当前状态（2026-07-21）

工作流前端已经完成真实四节点最小闭环：

`Start -> HTTP -> LLM -> End`

当前不是 Mock 执行。页面通过真实登录态、真实 agentId、真实保存接口和真实 SSE 运行接口与现有后端联调，已在浏览器完成成功、失败、中断和再次运行验收。

阶段结论：四节点 MVP、单智能体生命周期和可扩展节点架构已经闭环。后续主线不再是补基础框架，而是按产品优先级持续增加真实业务节点。

已确认可用：

- agentId 只从路由读取；路由无 ID 时按新增工作流处理。
- 新增工作流默认只有 Start 和 End，首次保存成功后把后端返回的真实 ID 写入路由。
- 有 ID 时读取 `agentSetting`，反序列化节点、连线、配置和视口。
- 使用 TanStack Query 调用模型列表、读取、保存、删除等接口。
- 使用 `/gpt/base/workflows/run` 执行真实 SSE 工作流。
- 使用 lodash-es 深比较持久化 payload；有未保存修改时禁止运行，改回已保存配置后自动恢复。
- Start、HTTP、LLM、End 均有独立节点模块、配置面板、协议转换、校验和运行详情。
- 节点支持 `idle / running / success / error / cancelled / skipped` 状态。
- 运行调试抽屉展示节点输入、输出、日志、耗时和错误，并支持复制。
- 运行期间，调试抽屉右下角发送按钮切换为红色停止按钮；停止后当前节点标为已中断，下游标为已跳过，并允许再次运行。
- 节点配置和调试运行共用右侧 Dock，两种模式互斥显示，不再覆盖画布；关闭调试后恢复节点配置。
- 调试会话关闭再打开时保留上次消息和节点运行结果，只有工作流保存成功、手动重置或切换智能体时清理。
- 节点配置和完整流程均支持查看、格式化和复制只读后端 JSON；不允许直接编辑 JSON 绕过节点契约与校验。
- HTTP 节点支持独立成功分支和异常分支，`catchError`、错误输出、Handle、序列化和连线校验已经闭合。
- HTTP 调试数据在前端递归脱敏 Authorization、Token、Secret、Password、Cookie 等敏感字段。

## 已知限制

- 当前后端主要在节点完成时返回完整 inputs / outputs，没有稳定的“节点已开始且携带输入”事件。因此运行中的节点可以被准确标为 running，但完整输入输出通常要等该节点结束后展示。
- 停止入口目前集中在运行调试抽屉，不在顶栏重复提供，避免两个停止控制源。
- HTTP 节点允许调用第三方地址；第三方 API Token 必须由业务侧提供，不能使用本系统登录 Token 代替。
- 多模态模型能力判断、附件入口动态显隐和附件绑定校验暂缓，后续根据明确业务需求补充；当前附件上传能力不作为四节点闭环验收阻塞项。
- 未引入 Vitest 等自动化测试依赖；当前按约定使用真实后端浏览器验收和轻量静态检查。
- React Router future flag 警告仍存在，但与工作流业务运行无关。

## 下一步

对话双生命周期基础已完成，“猜你想问”已作为 `transient` 临时交互接入统一 SSE 解析、卡片渲染和点击续问链路，不进入正式消息保存与历史恢复。当前编辑器尚未迁移参照项目隐藏的 `userGuide.questionGuide.open` 开关，因此只有后端已开启该能力的智能体会产生事件。

知识库引用已补齐参照项目的 AgentSearchData / sources / quoteQA 兼容解析、召回图片、分块详情、原文预览、Office 转 PDF 预览和下载交互；实时与历史继续复用同一 `reference` 数据和组件。当前后端环境仍无可用知识库及索引数据，因此真实检索与媒体验收暂缓。

循环体节点已完成前端实现与 TypeScript 检查：`loopRun` 独立注册为父容器，创建时自动附带不可删除的 `loopRunStart` / `loopRunBreak`，支持业务节点拖入拖出、父子坐标与 `parentNodeId` 双向转换、children 同步、内部变量作用域、动态循环输出、跨边界连线限制、运行状态和调试详情。运行验收已将 `currentItem` 修正为动态 `any`，并允许循环内普通末端节点无下游时自然结束本轮。现有后端真正闭环的是数组模式；条件模式仍是占位，且判断器 ELSE 未连线会被后端强制寻边并抛错，因此“IF 命中则终止、未命中则继续下一轮”尚未闭环。下一步继续验收不含判断器的普通数组遍历与保存恢复。

### 正式会话富内容上线边界（2026-08-24）

- 对话内容的完整能力矩阵、迁移状态、未迁原因和新增类型准入规则，以 `src/features/message-render/CHAT_CONTENT_CAPABILITY.zh-CN.md` 为唯一台账。
- 正式会话只展示能够同时实时渲染、消息落库和历史恢复的最终回复内容。
- 当前允许进入正式会话的内容为普通文本、基础图表（`echarts`）和知识库引用（`reference`）。
- “猜你想问”是明确的临时交互：两个对话入口实时一致，但不进入 `answer` / `contents`，刷新后不恢复。
- 数据库表格只允许在节点调试详情中展示；后端 `contents` 未定义表格类型，因此运行对话窗口与智能体助手均不展示。
- 推理过程按 `transient` 临时交互迁移：两个对话入口实时使用同一折叠组件，流式时默认展开、完成后默认折叠，不进入 `answer` / `contents`，下一轮提问前移除；只有推理没有正文时不得把推理降级为 durable Markdown。
- 节点状态、耗时、输入输出和分支信息属于节点调试体系，不属于对话内容。

每个新节点都必须同时交付：节点模块、配置面板、协议转换、变量契约、连接与业务校验、运行状态、调试详情和真实后端验收。不能只迁移节点外观。
