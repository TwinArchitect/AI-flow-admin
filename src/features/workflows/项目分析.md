# 工作流迁移联调待确认事项

## 1. 说明

本文档仅记录工作流迁移和联调中实际观察到、可能需要进一步确认或改进的事项。已经正常运行并完成闭环的能力不再展开。

以下内容用于协助前后端统一业务边界和协议，不作为责任判断。

---

## 2. 节点与工作流数据

### 2.1 参照项目旧数据不纳入兼容范围

**观察到的情况**

参照前端的校验主要覆盖开始/结束节点、环路、节点是否存在和部分变量引用；节点配置、分支连线、句柄、输出字段和类型等限制相对宽松，画布连线也基本直接保存。

当前项目增加了更完整的节点契约和运行校验，因此参照项目产生的部分旧工作流可能存在：

- 缺少当前节点要求的配置字段；
- 使用旧字段、旧输出名或旧连线句柄；
- 分支数量与连线数量不一致；
- 引用了已经不存在的节点或输出；
- 包含当前未注册或后端尚不支持的节点；
- 可以在参照前端打开，但无法按现有后端语义运行。

**建议**

参照项目旧数据不纳入当前项目的兼容范围，不为缺失配置、无效连线或无法确认的业务语义增加自动修复逻辑。

- 新项目继续执行当前节点配置、变量、连线和运行路径校验；
- 旧数据无法满足当前契约时，明确提示版本不受支持，建议重新编排；
- 不猜测字段、不补造连线，也不静默删除后再覆盖原始数据；
- 如需排查，可以保留原始 JSON 供人工参考，但不承诺可以直接编辑或运行。

建议从当前版本开始增加 `schemaVersion`，用于保障本项目后续版本升级，不用于兼容参照项目此前产生的不规范数据。

### 2.2 运行前保存的数据一致性保护

**观察到的情况**

当前运行接口提交的是智能体 ID、用户消息、变量和附件，不会把画布上的 `modules` 和 `edges` 草稿一并提交。后端实际执行的是该智能体最后一次保存的工作流配置。

如果画布修改后不保存就直接运行，界面展示的配置与后端实际执行的版本可能不一致。参照前端虽然没有明显的“请先保存”限制，但在当前接口契约下，如未自动保存，同样只能执行已落库版本。

**建议**

“运行前保存”属于当前接口约束下的数据一致性保护，不建议直接取消。为了减少操作步骤，可以在点击运行后先校验并自动保存，保存成功后继续运行；保存失败则不发起运行，并明确提示当前配置尚未生效。

### 2.3 判断器扩展操作符

**观察到的情况**

参照前端提供非空判断和若干长度比较操作符，配置可以保存；当前后端判断器尚未观察到对应执行逻辑。

**建议**

请确认这些操作符是否属于正式能力。如近期不支持，建议通过能力标识让前端隐藏；如需要支持，建议补充统一的操作符枚举和执行语义。

### 2.4 循环体中的判断器 ELSE

**观察到的情况**

循环场景通常需要“IF 命中则终止，未命中则自然进入下一轮”。当前判断器未命中时会继续查找 ELSE 连线；没有连接 ELSE 时，后端会返回“未找到分支边”。

**建议**

建议明确循环体内的自然继续规则：判断器未命中且 ELSE 未连接时，正常结束本轮并进入下一轮。循环体外可以继续保持原有分支校验。

### 2.5 条件循环

**观察到的情况**

数组循环已有实际执行基础；条件循环目前更接近按固定最大次数执行，尚未形成完整的条件表达式、终止条件和安全上限协议。

**建议**

建议当前优先开放数组循环。条件循环待表达式、终止规则、最大次数和超限错误明确后再作为正式能力开放。

### 2.6 变量更新的数据类型

**观察到的情况**

参照前端提供目标数据类型选择，当前后端主要按原值赋值，类型字段暂未用于转换或校验。

**建议**

请确认该字段是展示信息还是运行规则。如属于运行规则，需要明确类型转换和失败行为；如暂不转换，建议前端不展示该选择，避免形成错误预期。

### 2.7 文件解析

**观察到的情况**

上传和执行链路可以跑通，但文件解析服务获取附件信息的路径与文件服务实际查询路径存在差异。文件类型未被正确识别时，PDF、Word、Excel 等二进制文件可能按文本读取并返回不可读字符。

**建议**

- 统一附件详情接口路径和响应字段；
- 根据真实扩展名或 MIME 类型选择解析器；
- 明确支持的文件格式及不支持格式的错误提示；
- 提供标准文件用于联合验收。

前端建议继续展示后端解析结果，不在浏览器内另建一套办公文件解析逻辑。

### 2.8 知识库搜索

**观察到的情况**

当前联调环境缺少可用知识库、索引和文档数据，尚未完成真实召回、引用片段、引用图片和文档预览验收。

参照前端还提供重排权重配置；当前后端可以读取重排开关和模型，但暂未观察到权重字段参与计算。

**建议**

- 准备一个完成切片和索引的测试知识库；
- 提供稳定的引用结果字段样例；
- 确认重排权重是否属于正式能力，不使用的字段建议暂不展示。

### 2.9 Python 代码执行

**观察到的情况**

JavaScript 已验证正常。参照前端提供 Python 选项，但当前后端仍通过 JavaScript 执行链路处理 Python 配置。

**建议**

如近期不提供 Python，建议前端只展示 JavaScript；如计划提供，需要进一步明确运行沙箱、依赖、超时及输入输出协议。

### 2.10 图表输出字段

**观察到的情况**

当前实际可用链路是通过 `chartData` 返回 ECharts 配置。后端同时保留 `chartBase64`，但目前没有实际生成图片。

**建议**

建议确认以 ECharts JSON 作为正式图表协议。若不再需要服务端图片，可逐步废弃 `chartBase64`，避免对接方同时适配两种输出形式。

## 3. 统一消息链路与富内容

参照项目的调试运行和正式会话已经共用 SSE 解析、富内容注册和消息渲染组件。两者的合理差异是：调试运行不保存消息，正式会话需要落库和历史恢复。

当前需要关注的是保证同一种业务内容在两个入口中的实时展示一致，并明确它是否需要持久化。

### 3.1 数据库表格历史恢复

**观察到的情况**

数据库查询结果可以在调试和正式会话中实时展示为表格，但当前后端消息内容类型主要覆盖 `reference` 和 `echarts`，尚无数据库表格的持久化类型。

**影响**

实时会话可以看到表格，刷新或重新进入历史会话后无法恢复为相同效果。

**建议**

如果数据库表格需要进入正式会话，建议增加表格消息 Schema，至少明确列、行、标题、数据量限制和历史查询格式。在协议明确前，建议只作为调试或临时展示能力。

### 3.2 知识库引用完整验收

**观察到的情况**

基础引用消息已经具备实时展示和历史恢复能力，但引用图片、文档预览和下载仍缺少真实知识库数据验证。

**建议**

建议提供一份包含文本片段、文档信息和媒体资源的完整消息样例，并明确哪些字段落库、哪些资源通过文件 ID 动态查询。

### 3.3 临时内容和持久内容的标识

**观察到的情况**

推理过程和“猜你想问”更适合作为本次交互的临时内容；普通文本、图表和知识库引用属于需要历史恢复的持久内容。目前这一边界主要由前端按照内容类型判断。

**建议**

建议在事件或消息内容中明确生命周期：

- `durable`：实时展示、落库并支持历史恢复；
- `transient`：仅在当前交互中展示，不进入聊天历史。

这样后续新增内容类型时，前端无需再次判断是否保存，也能保证调试运行与正式会话使用相同解析规则。

### 3.4 “猜你想问”启用条件

**观察到的情况**

后端可以在工作流结束后发送 `question_guide` 建议，但编辑端目前没有清晰的启用配置入口。

**建议**

请确认该能力是否正式开放，以及由哪个配置字段控制。该内容可以按 `transient` 处理，不必写入历史消息。

### 3.5 会话与智能体的关联边界

**观察到的情况**

前端发送消息时会携带智能体标识。为避免切换智能体后复用不匹配的上下文，仍需确认后端的会话分组、消息查询和上下文加载是否均以智能体标识作为边界。

**建议**

建议明确一个会话只能属于一个智能体，并在创建会话、追加消息和查询历史时保持相同约束。

---

## 4. 建议优先确认

1. 明确参照项目旧数据不纳入兼容范围，并从当前版本开始记录数据版本；
2. 保留运行前的数据一致性保护，并确认是否采用“自动保存后运行”；
3. 文件类型识别与办公文件解析；
4. 循环体内判断器未连接 ELSE 时的执行语义；
5. Python 选项与实际执行能力的一致性；
6. 数据库表格是否需要进入正式会话历史；
7. 知识库真实数据和完整引用消息验收。
